# Jetson Orin Nano (Ubuntu 22.04 LTS aarch64 / JetPack 6.x 계열) 전용 의존성 목록
# 22.04의 기본 파이썬은 3.10이고, 이 코드베이스는 3.10에서 그대로 돈다
# (3.11 전용이던 asyncio.timeout은 bootstrap.async_timeout으로 대체됨).
# ---------------------------------------------------------------------------
# requirements.txt를 그대로 쓰지 않는 이유는 세 가지다:
#   1) opencv / onnxruntime 은 aarch64에서 pip 기본 휠이 정답이 아니다(아래 주석 참고).
#   2) 일부 패키지는 pip이 아니라 apt로 깔아야 한다(tkinter, PortAudio).
#   3) 몇 개는 aarch64 휠이 없어 소스 빌드가 필요하고, 실패해도 로봇은 돌아야 한다.

# ⚠️ 이 파일의 버전·경로는 실물에서 검증하고 채워 넣을 것. 여기 적힌 값은 "이 순서로
#    설치하고, 설치 후 scripts/jetson_doctor.py 로 확인하라"는 절차이지 검증된 핀 목록이
#    아니다. 확인이 끝나면 실제로 깔린 버전을 여기에 못 박아 재현 가능하게 만들 것.
#    (설치 절차 전체는 docs/jetson.md)

# === 0단계: apt (pip으로 못 깖) ===
#   sudo apt update
#   sudo apt install -y python3-pip python3-dev python3-venv python3-tk \
#                       libportaudio2 portaudio19-dev \
#                       v4l-utils build-essential cmake
#   - python3-venv      : 22.04는 venv가 기본 포함이 아니다 — 없으면 python3 -m venv 실패

#   - libportaudio2     : sounddevice의 실체. 없으면 import 자체가 실패한다
#   - portaudio19-dev   : sounddevice 빌드가 필요할 때
#   - v4l-utils         : 카메라 진단(v4l2-ctl --list-devices)
#   - build-essential   : pyworld 등 소스 빌드용

# === 2단계: 별도 취급이 필요한 것들 (위 목록에 일부러 안 넣음) ===
#
# opencv
#   pip의 opencv-python 휠은 GStreamer 지원 없이 빌드되어 있어 CSI 카메라
#   (nvarguscamerasrc) 경로를 못 쓴다. USB 웹캠만 쓴다면 pip으로 충분하다.
#     USB 웹캠만:  pip install opencv-python
#     CSI 카메라도: sudo apt install python3-opencv   (JetPack 제공 빌드, GStreamer 포함)
#   ⚠️ 함정: 아래 1단계의 mediapipe가 opencv-contrib-python을 의존성으로 끌고 온다
#      (pip show mediapipe 로 확인됨). apt로 GStreamer 포함 OpenCV를 깔아놔도 pip쪽이
#      venv에 들어와 그쪽이 먼저 로드될 수 있다. CSI 카메라를 쓸 거면 설치 후 확인:
#        python -c "import cv2; print(cv2.__file__)"   # dist-packages(apt)인지 site-packages(pip)인지
#   어느 쪽을 골랐든 확인:  python scripts/jetson_doctor.py   → "GStreamer 지원" 줄
#
#   ⚠️ 함정 2 (2026-08-26 검증): mediapipe가 opencv-contrib-python을 끌고 오므로
#      USB 웹캠 경로라도 opencv-python을 따로 먼저 깔아두면 같은 cv2/ 경로에 두 패키지가
#      겹쳐 설치돼 파일이 깨진다(cv2.__version__ 사라짐 등). 반드시 opencv-python은 지우고
#      opencv-contrib-python만 남길 것(--force-reinstall로 정리):
#        pip uninstall -y opencv-python opencv-contrib-python
#        pip install --force-reinstall --no-cache-dir opencv-contrib-python
#      pip이 "insightface requires opencv-python" 경고를 내지만 무시해도 된다 —
#      opencv-contrib-python도 동일한 cv2 모듈을 제공하는 상위호환 패키지라 실제로는 충족됨.
#
# onnxruntime
#   pip install onnxruntime 은 **CPU 전용**이다. 그걸 깔면 얼굴인식이 GPU를 전혀 못 쓴다
#   (조용히 느려지기만 해서 알아채기 어렵다 — 그래서 vision/vision_brain.py가 실제
#    프로바이더를 시작할 때 찍도록 고쳐뒀다).
#   GPU를 쓰려면 **설치된 JetPack 버전에 맞는** onnxruntime-gpu 휠이 필요하다. NVIDIA가
#   Jetson용 휠을 따로 배포하므로, 보드의 JetPack 버전을 먼저 확인하고
#   (`cat /etc/nv_tegra_release`) 그 버전에 맞는 휠을 받아 설치할 것.
#   설치 후 확인:
#     python -c "import onnxruntime; print(onnxruntime.get_available_providers())"
#   → CUDAExecutionProvider 가 보여야 성공. 안 보이면 CPU로 도는 것이고,
#     그 경우 .env에 FACE_DET_SIZE=320 을 넣어 검출 해상도를 낮춰 버틸 수 있다.
#
#   ⚠️ 함정 2 (2026-08-26 Xavier NX 실물 확인): pip 최신 onnxruntime(1.23.2)은 import
#      시점에 core dump로 죽는다 — cpuinfo가 NVIDIA Carmel 코어를 "Unknown CPU vendor"로
#      못 알아보고 벡터 인덱스 assertion에 걸림. 1.19.2~1.20.1은 import는 되지만, 실제로
#      InferenceSession을 만드는 순간(=insightface가 얼굴인식 모델을 로드하는 순간) 같은
#      assertion으로 죽는다 — 그것도 **nvpmodel이 6코어 중 일부를 꺼둔 전원 모드일 때만**
#      (기본값 MODE_10W_DESKTOP이 그렇다. sess_options.intra_op_num_threads를 명시해도
#      안 고쳐짐 — 스레드 개수 문제가 아니라 ORT 내부 코어 topology 탐지 버그로 보임).
#      "그럼 6코어 모드로 바꾸면?"이라고 생각하기 쉽지만, 이 보드는 6코어 모드일수록
#      코어당 최대 클럭이 1.9GHz -> 1.42GHz로 낮아져서 media/voice_shift.py의 실시간
#      오디오 처리가 오히려 못 버틴다(scripts/test_playout_margin.py로 확인). 즉 "onnxruntime
#      버전만 바꾸면 전원 모드에 안 얽매여도 되는" 쪽이 정답이었다 — **1.18.1로 검증됨**
#      (4코어 MODE_10W_DESKTOP에서도 크래시 없이 정상 동작, CPUExecutionProvider).
#      1.18.1은 NumPy를 1.26.4로 끌어내리지만(1.x 전용 빌드) opencv-contrib-python/
#      mediapipe는 여전히 정상 임포트됨(pip이 버전 경고를 내도 무시 가능, 실측 확인됨).
#      pip으로 그냥 최신을 깔지 말고 반드시:
#        pip install onnxruntime==1.18.1
#
# === 3단계: 있으면 좋지만 없어도 로봇은 도는 것들 ===

#   코드가 없는 걸 감지해서 해당 기능만 끄고 계속 진행한다(2026-08-24 이식 때 그렇게 고침).
